# Open questions and assumptions

Appended by build tasks. Format: `- [<TASK-ID>] <question> — assumed: <what was chosen>`

- [S-01] The plan assumes older majors of Next, Nest, Tailwind, Zod and Prisma than the registry now serves — assumed: used the current stable majors (Next 16, Nest 12, Tailwind 4, Zod 4, Prisma 7), following what the official generators emit.
- [S-01] Nest 12's generator emits oxlint while Next's emits ESLint — assumed: one shared ESLint 9 flat config in `packages/config` for every workspace, because the plan asks for a single shared preset and `eslint-config-next` needs ESLint. ESLint 10 is the registry latest but `eslint-config-next` 16 targets 9.
- [S-01] Prisma's `latest` tag is a release candidate (8.0.0-rc) — assumed: pinned stable 7.10; revisit when 8 is released.
- [S-01] `nestjs-zod` 5.5 declares peer ranges that exclude Nest 12 — assumed: safe to use, since it imports and works (validated by the API e2e test); the peer range is stale. Re-check when it publishes a Nest 12 range.
- [S-01] Tailwind 4 has no JS config, so the plan's "Tailwind preset" — assumed: a shared `theme.css` with an `@theme` block in `packages/ui`.
- [S-01] BullMQ on native ESM cannot lazy-load ioredis from connection options — assumed: the worker passes a constructed `ioredis` client.
- [S-02] MinIO is no longer on Docker Hub — assumed: official `quay.io/minio/minio` and `quay.io/minio/mc` with unpinned `latest` tags; the exact release tags could not be looked up here. Pin them.
- [S-02] The API and worker refuse to start without `.env`, but a fresh clone has none — assumed: `pnpm infra:up` copies each `.env.example` to a gitignored `.env` when missing.
- [S-02] Nest does not load `.env` itself — assumed: the API and worker `dev` scripts run through `node --env-file=.env`.
- [S-03] The plan's `CLAUDE.md` says `pnpm check` includes API e2e and points at `apps/api/src/logger.ts` — assumed: neither is true yet, so the file states what `pnpm check` runs today and the real logger path, and adds a short "Stack notes" section.
- [S-03] The plan's `protect-files.sh` blocks `.env`, which would also block `.env.example` that `CLAUDE.md` tells sessions to edit — assumed: `.env.example` stays editable; `.env` and `.env.*` are blocked.
- [S-03] `docs/progress.md` ticks S-01..S-03 only, per the task, so it does not reflect any deferred verification (S-02's MinIO check) as a tick difference — assumed: deferrals are listed under "Notes and deferred work".
- [S-04] The task asks for CI on pull requests, but the build loop merges into `develop` without one — assumed: CI also runs on pushes to `develop`.
- [S-04] The task asks for images on merge to `main` — assumed: images are also built (not pushed) and boot-tested on every pull request, so a broken Dockerfile fails before merge.
- [S-04] ECS needs a way to pick up new images before Terraform exists (L-05) — assumed: a mutable `:staging` tag plus `update-service --force-new-deployment`, with a commit-tagged image pushed for rollbacks.
- [S-04] The AWS resources and GitHub variables do not exist yet — assumed: the deploy workflow stays dormant until `AWS_ROLE_ARN` is set; names default to `medtravel-staging` / `medtravel-<app>` and can be overridden.
- [S-04] `dump.rdb` (a Redis snapshot holding only a test key from verification) was committed in S-01 by `git add -A` — assumed: remove it and ignore `*.rdb`; it stays in history but contains no secrets.
- [S-05] The task's brand tokens are placeholders (`<colour>`, `<font>`) — assumed: primary clinical blue (continuing S-01), secondary warm amber, Inter for Latin and Noto Sans Arabic for Arabic (IBM Plex Sans Arabic not bundled). One file (`theme.css`) to change.
- [S-05] "Set up shadcn/ui inside packages/ui" — assumed: the shadcn conventions (Radix + class-variance-authority + `cn`, components in place) without its CLI, which needs a registry download; no `components.json`.
- [S-05] TanStack Table 9 and react-day-picker 10 are the registry latest — assumed: use the 8.x and 9.x lines, whose APIs are known, and upgrade deliberately.
- [S-05] Arabic number formatting — assumed: Latin digits for dates, money and phone numbers, because they are compared against invoices and passports; one line (`intlLocale`) to change.
- [S-05] Case stages are needed by StatusBadge/StageTracker before F-10 — assumed: identifiers only in `packages/contracts/src/case-stages.ts`; F-10 adds transitions, owners and durations.
- [S-05] The gallery needs a storage endpoint to demo uploads — assumed: a mock S3 multipart endpoint in the portal, off in production unless `ENABLE_UI_GALLERY=true`.
- [S-05] Components carry no default text — assumed: every visible string is a prop supplied by the app through next-intl.
- [S-05] Dark mode — assumed: tokens and components are dark-ready and tested, but no toggle ships yet.
- [S-05] The S-01 Arabic brand name mixed scripts ("ميدتravel") — assumed: "ميد ترافل"; flagged in `packages/i18n/REVIEW.md`.
- [S-06] Authentication does not exist yet but the portals must redirect by role — assumed: a stub login (pick any of the eleven roles) that sets a cookie holding the role, switched on only by `ENABLE_STUB_AUTH=true`; F-03 replaces it.
- [S-06] Which routes are "the five route groups" — assumed: `/{locale}/patient`, `/ops` (the coordinator portal, PRD section 6), `/hospital`, `/agent`, `/admin`; one role belongs to exactly one portal (PRD section 2).
- [S-06] Whether a role sees only part of its portal (interpreter, finance) — assumed: not yet; every role sees its portal's whole menu until the permission matrix (F-04).
- [S-06] How to show screens that belong to later tasks — assumed: a placeholder page per PRD feature with its priority (launch, phase 2, phase 3); Case 360 is `/ops/cases/CASE-YYYY-NNNNNN`, the rest are flat pages.
- [S-06] The WhatsApp number — assumed: `NEXT_PUBLIC_WHATSAPP_NUMBER` at build time; the button is hidden when it is not set, rather than shipping a fake number.
- [S-06] What the header's "menus" contain — assumed: links to index pages (Treatments, Hospitals, Doctors, Destinations, Cost calculator, About) until the CMS has content for mega-menus.
- [S-06] Currency switcher scope — assumed: USD, EUR, INR, AED stored in a `mt_currency` cookie; nothing reads it until prices are shown (F-09 and the cost calculator).
- [S-06] Logo and favicon — assumed: a placeholder mark (blue square, white cross, amber arc) drawn for this task; replace with the real brand.

- [F-01] Money column width — the task says `Int`; used `BigInt` instead, because UZS, IQD and NGN prices exceed 32 bits (ADR 002). Say so if `Int` was intended.
- [F-01] Patient passport number is in the patient search vector, as the task asks — this keeps it in clear text in a searchable column. Alternative: a blind index (hash) so staff search by exact passport number only. Which do you want?
- [F-01] Entities beyond the task's list — assumed: added `StaffProfile`, `HospitalStaff`, `Accreditation`, `CaseAttendant`, `CaseStageHistory`, `DocumentShare`, `CommissionRule`, `MessageAttachment`, `StayHospitalDistance`, `NumberSequence` and the translation tables, because PRD sections 5 to 9 need them.
- [F-01] How hospitals get at patient documents — assumed: through `DocumentShare` rows (per document and hospital, revocable, tied to a `Consent`), never a flag on the document.
- [F-01] Generated versus trigger-maintained search columns — assumed: triggers, because Prisma tries to drop the default of a generated column in every later migration.
- [F-01] Seed scope — assumed: master data with Arabic names now; users, hospitals and cases in F-11.

- [F-02] Where the stub sign-in lives for the API — assumed: `ENABLE_STUB_AUTH=true` with a role in the `x-stub-role` header or the portal's `mt_stub_session` cookie, refused at boot when `NODE_ENV=production`; F-03 replaces it.
- [F-02] Who may change master data — assumed: any signed-in role may read, only `super_admin` may create, change, delete or restore (finance in the admin portal sees a read-only list); F-04 owns the real matrix.
- [F-02] URL of the screen — the task says `/admin/masters`, the S-06 placeholder was `/admin/master-data`; renamed the nav key to `masters`.
- [F-02] Countries, languages and currencies — assumed: deactivated, never deleted (no `deletedAt`, referenced by almost everything); the delete endpoint answers 409.
- [F-02] "All countries" — assumed: every ISO 3166-1 country libphonenumber knows (245), with CLDR names in English and Arabic and a region only for the markets the PRD names.
- [F-02] 10 languages — assumed: en, ar, ru, fr, uz, sw, am, bn, fa, hi (the source markets in PRD 1); only en and ar are active because only they are translated.
- [F-02] Lost reasons — assumed: the five of PRD section 3 (price, chose another country, no response, visa refused, medically unfit) plus chose another provider, treated at home and other.
- [F-02] Currencies — the task's 11 exactly (the F-01 seed's Kuwaiti dinar and yen are gone); minor units follow ISO 4217 (OMR and IQD have 3).
- [F-02] Where Arabic goes — assumed: only Arabic is translatable at MVP (`translations.ar`), English lives on the row; adding a language later means widening `translationLocaleSchema`.

- [F-03] Session lifetime — assumed: access cookie 15 minutes, refresh 30 days rotating (a replayed old token ends the session after a 10 second grace), so a signed-in browser stays signed in for 30 days of use.
- [F-03] Which roles need two-factor — assumed: every staff role, hospital desk, doctor and super_admin (PRD 12); patients, attendants and agents may enable it. A role that needs it but has none gets a limited session that can only reach the set-up page.
- [F-03] Lockout — assumed: five wrong passwords or codes lock the account for 15 minutes; the answer is the same for unknown and known addresses.
- [F-03] Password policy — assumed: at least 10 characters with a letter and a digit (PRD gives no rule).
- [F-03] Who can invite whom — assumed: super_admin invites staff and hospital users, a hospital desk its own hospital's staff, a patient their attendants; agents sign up by invitation only.
- [F-03] Patient sign-up — assumed: open registration for patients with email and password, or a one-time code by email or phone; the email is verified by a link but sign-in does not wait for it.
- [F-03] Magic link for doctors — assumed: a hospital desk issues it for one case the hospital has received, valid up to 72 hours, session capped at 8 hours and scoped to that case.
- [F-03] Dev sign-in — assumed: `AUTH_DEV_SKIP_2FA=true` lets staff without two-factor in, only when `NODE_ENV=development`; CI and tests enforce it.

- [F-04] Case manager "team" — assumed: cases owned by staff with the same `managerId`; a staff profile with `isManager` sees every case; a case manager with no manager sees only their own.
- [F-04] Ground coordinator "in their city" — assumed: the city of the hospital the case is sent to, or the preferred city while no hospital is chosen; "arrival within ±30 days" is the planned arrival date.
- [F-04] Interpreter and medical reviewer scopes — assumed: an interpreter sees cases with a booking assigned to them; a reviewer sees cases assigned to them plus unassigned cases in the medical review stage.
- [F-04] Agent scope — assumed: every user of an agency sees all of the agency's referrals (owner and sub-users); agents see case number, name, stage and status only, and never documents, money or medical data (PRD 2 and 12). Sharing status with agents needs the patient's consent (PRD 12), to be checked when the agent case list is built (F-10).
- [F-04] Doctor scope — assumed: a doctor sees a case only through an opinion request that names their doctor record; a hospital desk sees every case sent to its hospital.
- [F-04] Finance — assumed: sees every case's identity, stage and money fields, but no medical fields and no documents; invoices and payments are theirs.
- [F-04] Who exports — assumed: only roles with a reports permission (agent: own referrals, case manager: team, finance, super admin; the audit log by super admin only).
- [F-04] Attendants — assumed: see the case, travel, visa and chat of the patient they are attached to, and can upload their own passport; not the medical record.
- [F-04] Agents and consent — assumed: an agency sees a referral only while the patient has an unwithdrawn `share_stage_with_agent` consent for that agency, and then only case number, name, stage and status.
- [F-04] Hospital access ends — assumed: when the opinion request is declined, expired or cancelled, or the patient withdraws the consent, the hospital loses the case and its documents at once.
- [F-05] Download alert — assumed: more than 50 `document.downloaded` events by one user in any rolling hour opens one `Incident` (type other, severity high) per user per clock hour and notifies every active super admin in the app; sharing a download count across a team is not considered.
- [F-05] What the trail masks — assumed: passwords, tokens, secrets, hashes and one-time codes entirely; date of birth, email, phone and address entirely; passport numbers down to their last four characters. An update stores only the changed fields.
- [F-05] Who reads the audit log — assumed: super admin only (read and export); the PRD names no other role.
- [F-05] Retries — assumed: an outbox event is tried 6 times with 5 s, 10 s, 20 s ... waits before it is marked failed.
- [F-05] "Automatically for every create/update/delete" — assumed: detailed rows are written by each service in its transaction; an interceptor guarantees a plain route-level row for any signed-in change that wrote none. A database-level hook was not built (see docs/progress.md).
- [F-06] Which files and how big — assumed: PDF, JPG, PNG, HEIC, DOCX and ZIP, up to 500 MiB each; a ZIP is taken to be DICOM and is only scanned, not opened.
- [F-06] "Quarantined" — assumed: an infected file (or one that is not what it declares, or cannot be read) is moved to `quarantine/` in the bucket, never offered again, and the uploader is told in the app.
- [F-06] Watermark — assumed: PDF and JPEG/PNG up to 50 MB carry the viewer's name, the date and the case number on every download and preview; other types are delivered unmarked and say so in the audit row.
- [F-06] Who shares — assumed: only the patient who owns the document decides which hospital sees it; turning a hospital on is their consent for that case and hospital (wording version `share-medical-v1`); the hospitals offered are those with an opinion request for the case.
- [F-06] Who uploads where — assumed: a patient to their own file or a case of theirs, an attendant only a passport to an attached case, staff to a case they may see (hospital desks tag the file with their hospital); only staff may mark a file internal.
- [F-07] Where do templates live — assumed: in code (`packages/notifications/src/templates`, en and ar), reviewed with the code; a database table with an admin editor can follow when someone needs to change wording without a release.
- [F-07] Which channels for which message — assumed: patients and agents get WhatsApp first with email as the record copy (SMS as well for urgent reminders: pickup, appointment); staff get in-app and email. A person can switch off email, WhatsApp and SMS, never in-app or security alerts.
- [F-07] Retries — assumed: five attempts with the outbox's exponential backoff, then the message is marked failed; a refusal the provider marks final (a bad number) fails at once.
- [F-07] WhatsApp free text — assumed: allowed only within 24 hours of the person's last WhatsApp message to us; otherwise the approved template is sent.
- [F-07] Who may read the log — assumed: the super admin only (new permission subject `NotificationLog`).
- [F-08] Who may join which room — assumed: exactly who may read the case over the REST API (staff scope, the patient's own cases, hospitals with consent, never agents); a magic-link doctor only their one case.
- [F-08] How fresh must pushes be — assumed: a couple of seconds is fine for business events (they go through the outbox); typing is immediate.
- [F-09] Which exchange-rate provider in production — assumed: Frankfurter (ECB, free) is enough to start; Open Exchange Rates when a currency we sell in is missing. Rates are refreshed daily at 06:00 India time and a rate older than 3 days is refused rather than guessed.
- [F-09] Rounding of converted prices — assumed: half-even on the final minor unit; a quote stores the rate it used, so a converted price never changes after it is sent.
- [F-09] Which language a first-time visitor sees — assumed: their earlier choice, then the browser's language, then the language of their country (Arabic-speaking countries), then English.
