# 002 — Database conventions

- **Status:** accepted
- **Date:** 2026-10-22
- **Source:** task F-01 (`docs/BUILD_PLAN.md`), PRD section 11.

## Context

F-01 creates the whole schema (71 tables, PRD section 11) in one go, so the conventions every later
module relies on are fixed here, before any of them is written.

## Decisions

1. **UUID primary keys generated by the database** (`gen_random_uuid()`), not by Prisma, so raw SQL, the
   worker and future importers get the same keys. Country, Language and Currency are keyed by their ISO
   or BCP 47 code, which is already unique and readable in joins.
2. **Money is a 32-bit `Int` in minor units plus a currency code** that is a foreign key to `Currency`.
   This follows the task and `CLAUDE.md` ("never floats"). The cost: a column tops out at 21.4 million
   major units of a 2-decimal currency (about 2.1 crore rupees). That is far above any single
   payment, quote or invoice line here; **totals are summed in the application**, not in a column. If a
   single amount could ever exceed that (a pass-through hospital deposit for a multi-organ case, say),
   widen that one column to `BigInt` in a new migration.
3. **Rates are basis points** (`Int`, 0 to 10000) rather than decimals, so percentages are exact. Exchange
   rates are `Decimal(18,8)` because they are rates, not amounts, and are stored with each quote and payment.
4. **Soft delete** (`deletedAt`) on business records. Append-only tables, rows that live and die with their
   parent, and the small reference tables do not have it (a test lists the exceptions).
5. **Full-text search uses a trigger-filled `tsvector` column**, not a generated column. Prisma cannot
   express generated columns and, once it sees one, tries to `DROP DEFAULT` it in every later migration.
   The trigger approach gives the same result, needs no workaround, and keeps `prisma migrate dev` quiet.
   An immutable `f_unaccent()` wrapper makes searches ignore diacritics; the `simple` configuration keeps
   names intact in every language.
6. **Rules Prisma cannot express** (value checks, one current summary per case, append-only audit) are in the
   migration SQL, and `packages/db/test` proves each one against a real PostgreSQL.
7. **Enums mirror `packages/contracts`.** Prisma needs them declared in the schema, so a test compares
   every value and its order with the contracts and fails when they differ.
8. **No foreign keys on `AuditEvent`**, so the audit trail outlives (and can describe) deleted records.
9. **Translations are `<Entity>Translation` tables**, one row per language, with the English text on the
   entity itself.
10. **A numbered migration per task**, never edited once committed (`migrations/<timestamp>_<task>_<slug>`).

## Consequences

- Reports that sum money must do it in SQL (`sum()` returns a `bigint`) or in application code, never by
  reading a precomputed column.
- Adding a language means rows in `Language` and the translation tables, not a migration.
- Adding an enum value is a migration (`ALTER TYPE ... ADD VALUE`) plus a change in `packages/contracts`;
  the parity test catches one without the other.
