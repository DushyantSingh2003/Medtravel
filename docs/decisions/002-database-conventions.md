# 002 — Database conventions

- **Status:** accepted
- **Date:** 2026-10-22
- **Source:** task F-01 (`docs/BUILD_PLAN.md`), PRD section 11.

## Context

F-01 creates the whole schema (75 tables, PRD section 11) in one go, so the conventions every later
module relies on are fixed here, before any of them is written.

## Decisions

1. **UUID primary keys generated by the database** (`gen_random_uuid()`), not by Prisma, so raw SQL, the
   worker and future importers get the same keys. Country, Language and Currency are keyed by their ISO
   or BCP 47 code, which is already unique and readable in joins.
2. **Money is a `BigInt` in minor units plus a currency code** that is a foreign key to `Currency`.
   A 32-bit column tops out at about 21 million major units of a 2-decimal currency, which a price in UZS,
   IQD or NGN passes easily (a 20,000 USD package is 25 billion minor units in som). `BigInt` removes the
   ceiling; the API contracts carry amounts as strings or `bigint`-safe numbers. Wherever an amount is
   optional, a `CHECK` requires its currency to be present, and a test lists every money column.
3. **Rates are basis points** (`Int`, 0 to 10000) rather than decimals, so percentages are exact. Exchange
   rates are `Decimal(18,8)` because they are rates, not amounts, and are stored with each quote and payment.
4. **Soft delete** (`deletedAt`) on business records. Append-only tables, rows that live and die with their
   parent, and the small reference tables do not have it (a test lists the exceptions).
5. **Full-text search uses a trigger-filled `tsvector` column**, not a generated column. Prisma cannot
   express generated columns and, once it sees one, tries to `DROP DEFAULT` it in every later migration.
   The trigger approach gives the same result, needs no workaround, and keeps `prisma migrate dev` quiet.
   An immutable `f_unaccent()` wrapper makes searches ignore diacritics; the `simple` configuration keeps
   names intact in every language.
6. **Rules Prisma cannot express** (about 47 value checks, partial unique indexes for the one-at-a-time rules,
   consent-bound document sharing, append-only audit) are in the migration SQL, and `packages/db/test` proves each one against a real PostgreSQL.
7. **Enums mirror `packages/contracts`.** Prisma needs them declared in the schema, so a test compares
   every value and its order with the contracts and fails when they differ.
8. **No foreign keys on `AuditEvent`**, so the audit trail outlives (and can describe) deleted records; its
   `entityId` is text so it can also describe rows keyed by a code. Updates and `TRUNCATE` are rejected by
   triggers. A table owner can still drop the trigger: the production application role must therefore not own
   the tables (a deployment task, recorded in `docs/progress.md`).
9. **Hospital access to documents is never a flag.** A `DocumentShare` row needs a `Consent` of the right
   type, patient and hospital, enforced by a trigger; withdrawing the consent revokes its shares.
10. **Patient search includes the passport number**, as the task asks, so staff can find a patient by it. The
   trade-off (a searchable column holds the number in clear text) is raised in `docs/questions.md`; the
   alternative is a blind index.
11. **Translations are `<Entity>Translation` tables**, one row per language, with the English text on the
   entity itself.
12. **A numbered migration per task**, never edited once committed (`migrations/<timestamp>_<task>_<slug>`).

## Consequences

- Reports that sum money must do it in SQL (`sum()` returns a `bigint`) or in application code, never by
  reading a precomputed column.
- Adding a language means rows in `Language` and the translation tables, not a migration.
- Adding an enum value is a migration (`ALTER TYPE ... ADD VALUE`) plus a change in `packages/contracts`;
  the parity test catches one without the other.
