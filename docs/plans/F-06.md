# F-06 — Secure file service

## Goal

Patients, attendants and staff upload medical files straight from the browser to a private bucket (resumable multipart, up to
500 MB: PDF, JPG, PNG, HEIC, DOCX, ZIP of DICOM); the worker scans every file with ClamAV and quarantines infected ones,
reads the page count and makes thumbnails; downloads go only through an endpoint that checks permission and consent, writes an
audit event and returns a presigned URL valid 5 minutes, with PDFs and images watermarked; a document list with type tags,
preview, download, share-with-hospital toggles and soft delete.

Acceptance: a 300 MB ZIP uploads with progress, gets scanned, and only permitted roles can download it.

## Design

- **New package `@medtravel/storage`** (used by the API and the worker): `ObjectStore` (S3 through `@aws-sdk/client-s3`: head, stream,
  put, copy, delete, presigned GET and the presigned multipart requests), file helpers (magic-byte `sniffFileType`, PDF page
  count and watermark with `pdf-lib`, image thumbnail and watermark with `sharp`), and test doubles: `FakeS3Server` (an in-process
  S3-compatible server for path-style requests with presigned URLs, which also checks that a URL is not older than its
  `X-Amz-Expires`) and `FakeClamd` (speaks the clamd `INSTREAM` protocol, finds the EICAR test string). Neither MinIO nor ClamAV
  runs in the sandbox or in CI's browser job; real ones are in `infra/docker-compose.yml` for development and staging.
  New dependencies: `@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`, `pdf-lib`, `sharp`.
- **Upload (browser → bucket).** The shared `FileUploader` (Uppy, signed requests) asks `POST /documents/uploads/sign` for a
  presigned URL for every S3 call. The API validates each: the first (create multipart) carries the file's name, size and type
  and what it belongs to (case or patient, kind, type, visibility); the API checks the role may add documents there, the type and
  size are allowed, and chooses the object key itself (`files/<uuid>`, the name never reaches the bucket path), recording a
  `FileUpload` row. Later requests (parts, list, abort) must be for that key, by that user, while the upload is open and within
  the part count the size allows. The key and the 15-minute URLs are the only things the browser can use.
- **Completion.** `POST /documents/uploads/complete {key}` checks with the bucket that the object exists and its size equals
  the declared size (a longer or shorter object is deleted and refused), creates the `Document` in status `pending` (shown as
  "scanning") and writes a `document.uploaded` outbox event and an audit row in one transaction.
- **Scan and processing (worker).** The `document.uploaded` handler streams the object to ClamAV (`clamd` over TCP,
  `INSTREAM`); infected files are moved to `quarantine/` and the document is marked `infected` with the signature name. A clean
  file's first bytes must match its declared type (`type_mismatch` → quarantined, status `failed`). Then the page count (PDF) and
  a 320 px thumbnail (JPG, PNG) are made and the document becomes `clean`. A scanner that cannot be reached makes the event retry
  (outbox backoff); the document stays `pending` and cannot be downloaded.
- **Download and preview.** `POST /documents/:id/download` (and `/preview`, inline): the document must be visible to the caller
  (`ScopeService.documentWhere`: ownership, role scope, a live consent for hospitals; agents never) and `clean`; the access is
  written with `AuditService.recordAccess` (which also counts towards the download alert) before any URL exists; a PDF or
  JPG/PNG up to 50 MB is watermarked with the viewer's name, the date and the case number into a short-lived copy under
  `watermarked/` and that copy is presigned for 5 minutes; other types (HEIC, DOCX, ZIP) are presigned as they are
  (`watermarked: false` in the answer and the audit row). Disposition is attachment, with a sanitised file name.
- **Sharing with a hospital.** `PUT /documents/:id/shares/:hospitalId {shared}`: only the patient who owns the document. Turning it
  on records the patient's consent (`share_medical_with_hospital` for that case and hospital, with their address) if none is live,
  and creates or revives the `DocumentShare`; turning it off revokes the share. Candidates are the hospitals the case has an
  opinion request with. Both are audited.
- **List, update, delete.** `GET /documents` (cursor paging, filters case, patient, kind; always AND-ed with the scope),
  `GET /documents/:id`, `PATCH /documents/:id` (kind, type, notes), `DELETE /documents/:id` (soft; the object stays until
  retention). Every list row says who uploaded it and which hospitals it is shared with.
- **Data model** (migration `f_06_files`): `FileUpload` (the upload intent: key, user, file name, size, type, owner, status
  `open|completed|aborted|expired`, upload id, expiry) and new `Document` columns `pageCount`, `thumbnailKey`, `scannedAt`,
  `scanDetail`.
- **Portal and UI.** `DocumentList` in `packages/ui` (type tags, status, preview, download, share toggles, delete; no text inside,
  gallery entry in English and Arabic); `/patient/documents` page with the uploader, the list, a preview dialog and the share
  dialog. English and Arabic messages (`documents.*`).
- **Dev and CI without Docker.** `fake-s3` and `fake-clamd` scripts (from `@medtravel/storage`) stand in for MinIO and ClamAV in
  the browser job; `pnpm dev` keeps using the real containers.

## API

| Method and path                           | Permission              | Notes                                                            |
| ----------------------------------------- | ----------------------- | ---------------------------------------------------------------- |
| `POST /documents/uploads/sign`            | create Document         | one presigned URL per S3 request, validated against the upload  |
| `POST /documents/uploads/complete`        | create Document         | verifies size, creates the document, queues the scan            |
| `GET /documents`                          | read Document           | scoped; filters caseId, patientId, kind                          |
| `GET /documents/:id`                      | read Document           | 404 outside the scope                                            |
| `POST /documents/:id/download`            | read Document           | audited, watermarked, 5-minute URL                               |
| `POST /documents/:id/preview`             | read Document           | same, inline                                                     |
| `GET /documents/:id/thumbnail`            | read Document           | audited view, 5-minute URL                                       |
| `PATCH /documents/:id`                    | update Document         | kind, type, notes                                                |
| `DELETE /documents/:id`                   | delete Document         | soft delete                                                      |
| `GET /documents/:id/shares`               | read Document           | hospitals the case was sent to, and whether each is shared       |
| `PUT /documents/:id/shares/:hospitalId`   | update Document         | patient only; records consent                                    |

## Tests

- storage: sniffing, watermark and thumbnail output, presigned URL shape and 300 s expiry, fake S3 multipart round trip, fake
  clamd verdicts.
- API e2e (real PostgreSQL, fake S3): the whole upload (sign → parts → complete), every refusal (wrong type, too large, key of
  another user, part number out of range, size mismatch), list scoping per role, download refused to an agent, an attendant
  of another case, a hospital without a share or after the consent is withdrawn, 5-minute URL and audit row, share on/off
  with consent, soft delete, forbidden roles on every route.
- worker e2e: scan clean, scan infected → quarantine, type mismatch, scanner down → retry, page count and thumbnail.
- Playwright: a patient uploads a PDF and a 300 MB ZIP with progress, sees "scanning" then "clean" (worker and fake scanner
  running), previews, downloads, toggles sharing; a case manager of another case cannot see it.
