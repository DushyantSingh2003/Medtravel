# AD-02 — Hospital and doctor approvals

## Goal

The super admin reviews what partner hospitals submit and controls what the website shows: a queue of onboarding submissions, profile
edits and package price changes with a side-by-side diff; accreditation certificates verified; approve or reject with a reason; the
referral fee %, agreement dates and agreement document; publish and unpublish a hospital, doctor or package (the website is told to
refresh); and a partner health view (accreditation and agreement expiries, response-time trends). Acceptance: approving a price change
updates the website and the quote builder.

## Design

- **Data** (migration `ad_02_partner_approvals`): `PartnerChangeRequest` (kind `hospital_onboarding | hospital_profile | package_price`,
  status `pending | approved | rejected | withdrawn`, `current` and `proposed` JSON, note, decision reason, who and when);
  `Hospital.agreementStartsOn / agreementEndsOn / agreementDocumentId` (the referral fee stays `agreementBp`);
  `Accreditation.verifiedAt / verifiedById / verificationNote`; `Package.published` (existing packages that are active stay published).
  Check constraints: referral fee 0–10,000 bp, agreement end not before start.
- **Submitting** (`/hospital/change-requests`, `Hospital` update, scoped to the user's hospital; a super admin names the hospital):
  profile edit (whitelisted fields only), package price change, and submit-for-review (draft → pending_review). H-01 builds the hospital
  screens on these. One pending profile edit per hospital, one pending price change per package. A request stores what the fields held
  when submitted.
- **Deciding** (`/admin/partners`, `Setting`, super admin only): approve applies `proposed` in one transaction under a lock on the
  request and, in the same transaction, audits and writes outbox events; a request already decided is a 409. Approving onboarding makes the
  hospital `approved` (not published); rejecting it sends the hospital back to `draft`. The detail shows each field's submitted, live and
  proposed values and flags a field whose live value moved on since.
- **Publishing**: a hospital goes live from `approved` or `unpublished` only with a referral fee set and at least one accreditation that
  is verified and not expired. A doctor or package needs a published hospital (and an active package). Unpublishing is always allowed.
- **Website refresh**: every publish, unpublish and approved change to something already public writes a `web.revalidate` outbox event
  with cache tags (`hospitals`, `hospital:<slug>`, `doctor:<slug>`, `packages`). The worker posts them to the website's
  `/api/revalidate` (secret header) which calls `revalidateTag`. Unset URL or secret: the worker logs and skips (development).
- **Quote builder**: it reads `Package.priceMinor` and `currency`, which approval updates in the same transaction as the decision.
- **Partner health** (`GET /admin/partners/health`): accreditations and agreements expiring within 90 days (or already expired) and
  per-hospital monthly request counts and average response hours for the last six months (opinion requests: sent to answered).
- **Portal** `/admin/hospital-approvals`: tabs for the queue (filters, diff dialog with approve and reject), hospitals (status,
  referral fee, agreement; detail with accreditation verification, publish toggles for doctors and packages) and partner health.

## Assumptions

No notification to the hospital yet (new event keys need templates; deferred). Doctor profile edits are not a request kind (doctors
are published or not; their text is edited by the hospital in H-01 and not gated). A hospital's other fields are edited directly while
it is a draft. Agreement documents are uploaded through the existing file service and linked here by id.

## Review changes

Withdrawing takes the same lock as a decision; publishing, unpublishing, verifying and publishing a doctor or package share one lock per
hospital; tags are normalised to the website's syntax; the worker drops a 400 or 403 from the website instead of retrying for ever and
refuses to start in production without the website address and secret. Prices must be at least 1 minor unit; empty text clears a field.
