# S-02 — Local services with Docker

## Goal

`infra/docker-compose.yml` for local development with PostgreSQL 16 (`pg_trgm`, `unaccent`),
Redis 7, MinIO (private bucket `medtravel-private`, public bucket `medtravel-public`, both
auto-created), Mailpit and ClamAV; env vars wired into the `.env.example` files; `pnpm dev`
starts the containers, waits until healthy, then runs every app in parallel through Turborepo;
README "Getting started" with exact commands and every local URL.

## What was added

- `infra/docker-compose.yml` — six long-running services plus a one-shot `minio-init` job, all
  with healthchecks so `docker compose up --wait` blocks until everything is ready. Ports and
  credentials are overridable from the shell or a root `.env`.
- `infra/postgres/init/01-extensions.sql` — enables `pg_trgm` and `unaccent` on first start.
- `infra/minio/init-buckets.sh` — idempotent bucket creation: private bucket with no anonymous
  access, public bucket with anonymous read.
- `scripts/setup-env.mjs` — copies each `.env.example` to `.env` when missing, so a fresh clone
  boots with no manual steps (the API and worker refuse to start without `DATABASE_URL` and
  `REDIS_URL`).
- Root scripts `dev`, `infra:up`, `infra:down`, `infra:reset`, `infra:logs`.
- `turbo.json`: the `dev` task now depends on `^build`. Without it a fresh clone has no `dist`
  folders for the shared packages and the API/worker fail to import `@medtravel/contracts`.
- API and worker `dev` scripts run through `node --env-file=.env` (Nest does not load `.env`
  by itself; Next does).
- Root `.env.example` (compose overrides); S3, SMTP and ClamAV variables added to the API and
  worker `.env.example`.
- `README.md` with Getting started, a URL table and the command list.

## Not changed

No API endpoints, data model, permissions, UI or i18n keys. The API and worker `env.schema.ts`
files do not yet read the new S3/SMTP/ClamAV variables: the modules that use them (files,
notifications) add them to the schema when they exist, so S-02 does not add unused config.

## Tests

This task is infrastructure, so the verification is running it (see below) rather than unit
tests. There is no new user-facing flow for Playwright.

## Assumptions

- **Image tags.** `postgres:16-alpine`, `redis:7-alpine`, `axllent/mailpit:latest`,
  `clamav/clamav:stable`, and `quay.io/minio/minio:latest` / `quay.io/minio/mc:latest`. MinIO is
  no longer published on Docker Hub, so the official `quay.io` images are used. Unpinned tags
  were chosen over guessed pins because the exact current MinIO release tags could not be
  looked up from this environment; pin them once confirmed.
- **Secrets.** The credentials in the compose file and `.env.example` files are development
  defaults, not secrets. Real values never go in the repository.
- **`.env` auto-creation.** `pnpm infra:up` creates missing `.env` files. Existing ones are
  never overwritten.
- **Shared packages are not watched.** Editing a package during `pnpm dev` needs a rebuild;
  documented in the README.

## Verification

Run in this environment:

- `docker compose config` validates.
- Real containers, healthy via their own healthchecks: PostgreSQL, Redis, Mailpit, ClamAV.
- Functional checks: both extensions installed and working (`similarity`, `unaccent`); ClamAV
  returns `OK` for clean data and `FOUND` for the EICAR test file over TCP 3310; Mailpit receives
  an email over SMTP and lists it through its API; Redis stores and returns a value.
- From a state with every build output deleted, `turbo run dev` started the API, worker,
  website and portal; `/health`, `/docs`, website `/en` `/ar` and portal `/en` `/ar` all
  returned 200, and the worker connected to Redis without errors.
- `pnpm check` and `pnpm build` pass.

**Not verified here — MinIO.** This environment's network policy blocks `quay.io`, so the official
MinIO image could not be pulled and the `minio` and `minio-init` services, and therefore the
full `pnpm infra:up` / `pnpm dev` command, have not been run. The bucket script was tested
against a stand-in (an older Bitnami MinIO image that bundles the same `mc` client): both
buckets are created, repeated runs succeed, the private bucket returns 403 to anonymous reads
and the public one returns 200. The official image's `mc ready local` healthcheck is
unconfirmed. Run `pnpm dev` once on a machine with normal network access before relying on it.
