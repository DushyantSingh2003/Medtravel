# F-05 — Audit log and domain events

## Goal

An audit trail that records who did what to which record (with a masked before/after diff), who viewed or downloaded a
patient record or document, and an alert when one user downloads too many documents; a transactional outbox whose events the
worker dispatches to handlers with retries and idempotency; an admin screen to search and export the trail.

Acceptance: viewing a patient document shows up in the audit screen within seconds.

## Design

- **Audit writes** (`AuditService`, `apps/api/src/audit`): still called with the transaction client of the change it
  describes, so the row exists if and only if the change does. New: sensitive fields are masked (`maskSensitive`, in
  `packages/contracts`: passwords, tokens, secrets, one-time codes and hashes are replaced entirely; passport numbers keep
  the last four characters; date of birth, email and phone are masked) and an update stores only the **changed** fields
  (`diffAudit`) so a large row does not copy the whole record into the log. The pattern stays "every service that changes
  data records it in the same transaction" (CLAUDE.md); the masters module and the auth module already do. A spec guards
  the masking and the diff.
- **Views and downloads**: `AuditService.recordAccess(context, { kind, entityType, entityId, patientId })` writes
  `document.viewed`, `document.downloaded`, `patient.viewed` or `patient.exported` in its own transaction and returns once the
  row is committed, so the screen sees it at once. F-06 (files) and the patient screens call it on every read.
- **Download alert**: on `document.downloaded`, if the same user has made more than 50 in the last hour, the same transaction
  opens an `Incident` (type `other`, severity high; one per user per hour, guarded by a unique outbox key) and writes an
  `incident.created` outbox event. The worker's handler notifies every active super admin (in-app notification, once per
  event even if it is retried).
- **Outbox runtime** (`packages/db/src/outbox.ts`): `claimOutboxBatch` (one `UPDATE ... FOR UPDATE SKIP LOCKED`, safe with
  several workers; events stuck in `processing` become claimable again after a visibility timeout), `completeOutbox`,
  `failOutbox` (exponential backoff, `failed` after 6 attempts) and `processOutbox(prisma, handlers)`. The worker polls every 2
  seconds. Handlers are registered per event type and must be idempotent; each receives the event id as its idempotency
  key. Events with no handler are deferred for 10 minutes (not consumed), so a worker older than an event does not lose it.
- **Audit API** (`GET /audit`, `GET /audit/export`): `@Can('read'|'export', 'AuditLog')` (super admin only, per the matrix).
  Filters: `actor` (name or email fragment), `actorId`, `entityType`, `entityId`, `action`, `patientId`, `from`, `to`;
  cursor pagination on `(createdAt, id)`, newest first; actor names resolved in one batched query. Export streams CSV (up to
  10,000 rows) and is itself audited (`audit.exported`). Rows are returned as stored (already masked).
- **Admin screen** `/admin/audit` (nav key `audit-log` renamed `audit` to match the URL): filters for user, entity type,
  action and date range, the shared `DataTable` with cursor paging, a detail sheet showing the masked diff, and a CSV export
  button.
- **Seed**: a few sample events (a view, a download, a change) so the screen is not empty on a fresh database.

## API

| Method and path     | Permission      | Notes                        |
| ------------------- | --------------- | ---------------------------- |
| `GET /audit`        | read AuditLog   | filters above, cursor paging |
| `GET /audit/export` | export AuditLog | CSV, same filters, audited   |

## Events

`incident.created` (aggregate `Incident`) → in-app notification to super admins. Reserved types for the notification,
SLA and search-refresh handlers of later tasks are not registered yet.

## Tests

- contracts: masking (keys, nesting, arrays, partial passport), diff (changed, added, removed, equal), query schema.
- db e2e: claim batches without overlap under concurrency, retry backoff, `failed` after the limit, stuck events reclaimed,
  idempotent handlers, dedupe key refuses a duplicate.
- API e2e: list/filter/paging/export, forbidden roles (case manager, agent, patient get 403), access events appear in the list
  immediately, masking of a stored change, the 51st download opens exactly one incident and one outbox event.
- worker e2e: the dispatcher turns `incident.created` into one notification per active super admin, once.
- Playwright: the admin opens `/admin/audit`, sees events, filters by action, opens the detail, exports; a case manager is
  turned away.
