# F-09 — Money, currencies and languages

## Goal

One way to hold, calculate, convert, format and translate money and text: integer minor units everywhere, no floats; daily
exchange rates that quotes can snapshot; the right language and time zone for each viewer.

Acceptance: a price shows correctly in INR, USD and AED, in English and Arabic.

## Design

- **Money** (`packages/contracts/src/money.ts`): `Money = { amountMinor: number; currency }` (a safe integer; the database uses
  64-bit columns, and the API sends numbers while they fit). All arithmetic goes through `BigInt` so a large total cannot lose
  precision: `add`, `subtract`, `negate`, `compare`, `multiply(money, ratio, rounding)` (ratio as a decimal string such as
  `"0.125"` or a `{ n, d }` fraction, never a float; rounding half-even by default, `up`, `down`, `half_up`),
  `allocate(money, weights)` (largest remainder: the parts always add up to the whole, e.g. splitting an invoice or a
  commission), `convertMinor(amountMinor, fromDigits, toDigits, rate)` (rate as a decimal string with up to 8 places, as in
  `FxRate`). Mixed currencies throw. `formatMoney(money, locale, options)` uses `Intl.NumberFormat` with Latin digits in
  Arabic, the currency's own number of decimals (`currencyDigits`: 0 for JPY, 3 for KWD), and a compact option.
- **Exchange rates** (`packages/fx`): a provider interface (`fetchRates(base, quotes)`) with Frankfurter (ECB, no key),
  Open Exchange Rates (key) and a fixed `static` table for development and tests, chosen by `FX_PROVIDER`.
  `storeRates` writes `FxRate` rows (unique per pair and time, so a re-run changes nothing). `rateOn(prisma, from, to, date)` finds
  the newest rate not after the date: direct, inverse, or through the USD pivot; the answer carries the rate, its time, its
  source and whether it was derived. `convert(prisma, money, to, date)` and `snapshotRate` (the fields a quote stores:
  `fxRate`, `fxRateAt`, `fxSource`, `fxBaseCurrency`). Missing or stale rates (older than 5 days) are an error, never a guess.
- **Daily job** (`apps/worker`): a BullMQ job scheduler at 06:00 Asia/Kolkata (`FX_REFRESH_CRON`, default `0 6 * * *`) fetches the
  rates for the active currencies and stores them; a failure retries with backoff and leaves the old rates in place.
- **API**: `GET /fx/rates` (public, cached for an hour, rate limited) returns the newest USD-based table for the website;
  `GET /fx/convert?from=&to=&amount=&date=` converts an integer amount for signed-in users.
- **Website**: the currency cookie and header switcher already exist (S-06). New: `Price` in `packages/ui` (formats a `Money`, in
  a `<bdi>` so Arabic layout cannot reorder it) and `ConvertedPrice` in `apps/web` (reads the cookie and the rate table and
  shows the price in the chosen currency, with "approximately" when converted). The portal gallery shows a price in INR, USD
  and AED in both languages.
- **Locale detection**: `negotiateLocale({ cookie, acceptLanguage, country })` in contracts: the saved cookie first, then the
  browser's language, then the country (Arabic-speaking countries get Arabic), then English. The web middleware applies the
  country step when the first two give nothing (`cloudfront-viewer-country`, `cf-ipcountry` or `x-vercel-ip-country`).
- **Time zones** (`packages/contracts/src/time.ts`): `OPS_TIME_ZONE = 'Asia/Kolkata'`, `resolveTimeZone(user, fallback)`,
  `dayBoundary(day, 'start'|'end', zone)` (replaces the hand-written +05:30 in two screens), `formatDateTime`, `formatDate`.
- **Translated content**: `getTranslated(entity, translations, locale, fields)` returns each field in the viewer's language, falling
  back to the English value on the entity when a translation is missing or blank.

## Tests

Property-style specs for money (allocation sums, rounding modes, big numbers, currency mismatch, rate parsing); formatting for
INR, USD, AED, EUR, JPY and KWD in en and ar; locale negotiation matrix; time zone boundaries across DST zones; translation
fallback. Provider specs against a local HTTP server; worker e2e (job stores rates, idempotent, provider failure keeps old
rates); API e2e (`/fx/rates`, `/fx/convert`, forbidden anonymous convert, derived and stale rates); web component test and
Playwright on the gallery (INR/USD/AED × en/ar, axe).

## Assumptions

Rates are mid-market from the provider, shown as approximate; the booked price of a quote is whatever the quote snapshot says.
The static provider is refused in production. Display currencies stay USD, EUR, INR, AED (S-06); the stored currencies are the
`Currency` master.
