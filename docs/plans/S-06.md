# S-06 — App shells and layouts

## Goal

Everything around the screens, before any screen exists: the authenticated portal shell with five
route groups (`/patient`, `/ops`, `/hospital`, `/agent`, `/admin`) and a placeholder for every screen
named in PRD sections 5.2, 6, 7, 8 and 9; role-based redirect after a stub login; the public
website's header, footer and WhatsApp button; 404, error and loading states, SEO defaults and favicons
in both apps. Acceptance: you can click through every placeholder page of every portal.

## Data model, API, events

None. No database, endpoint or event changes. Authentication is a stub (see Assumptions).

## Shared components (`packages/ui`, with gallery sections in en and ar)

- `AppShell`: collapsible sidebar (icons only when collapsed, remembered per browser), top bar slot,
  mobile menu as a sheet from the reading-start edge, skip link, active-page marking.
- `Switcher` (language and currency), `UserMenu`, `NotificationsMenu`, `BrandMark`.
- `SiteHeader` (logo, menu, actions, mobile menu), `SiteFooter` (link columns, legal links),
  `WhatsAppButton` (floating).
- All take their text as props, like every other component here.

## Contracts

`packages/contracts`: `ROLES` (the eleven of PRD section 2), `PORTALS`, `portalOfRole`, and
`DISPLAY_CURRENCIES` (USD, EUR, INR, AED).

## Portal (`apps/portal`)

- `lib/portal-pages.ts`: the screen registry per portal (79 screens: key, icon, PRD priority, nav
  section). Titles and descriptions are messages `nav.*`, `pages.*`, `navSections.*`.
- Route group per portal: `app/[locale]/{patient,ops,hospital,agent,admin}/` each with `layout.tsx`
  (session check, shell with that portal's navigation), `[[...slug]]/page.tsx` (placeholder page, 404
  for unknown slugs; `ops/cases/[id]` is the Case 360 placeholder), `loading.tsx`, `error.tsx`.
- Stub auth: `/[locale]/login` lists the eleven roles; choosing one sets an `httpOnly` cookie holding
  the role and redirects to that role's portal. A user in the wrong portal is sent to their own.
  Sign-out clears it. Only works when `ENABLE_STUB_AUTH=true`; otherwise `/login` says sign-in is not
  available and every portal redirects to it.
- Top bar: search (UI only), notifications bell (empty), language switcher, user menu.
- `not-found`, `error`, `global-error`, `robots.ts` (disallow all), `noindex` metadata, favicon set.

## Website (`apps/web`)

- Public layout: header with Treatments, Hospitals, Doctors, Destinations, Cost calculator, About;
  language and currency switcher (currency kept in a cookie; nothing reads it until prices exist);
  "Get a free quote"; WhatsApp floating button (number from `NEXT_PUBLIC_WHATSAPP_NUMBER`, hidden when
  unset); footer with three link columns and the five legal pages.
- 15 placeholder pages so no menu or footer link is a 404, statically generated in both languages.
- `not-found`, `error`, `global-error`, `loading`, `robots.ts`, `sitemap.ts`, metadata defaults
  (title template, Open Graph, `metadataBase`, language alternates), favicon set and web manifest.

## i18n

About 280 keys in en and ar (`nav`, `navSections`, `pages`, `shell`, `roles`, `portals`, `priority`,
`placeholder`, `login`, `errors`, `site`). The Arabic is a machine draft, listed in
`packages/i18n/REVIEW.md`.

## Tests

- Unit: roles and portals; the registry (every screen has en and ar text, keys unique, every portal's
  home exists, all icons known); session cookie parsing; shell state helpers.
- Component tests for the new shared components; style guards cover them automatically.
- Playwright: sign in as every role and land in the right portal; **click through every placeholder
  page of every portal** from the sidebar, in English and Arabic; wrong-portal redirect; signed-out
  redirect; collapse/expand; mobile menu at 360 px; no horizontal overflow; axe on shell pages; 404 and
  error pages; website header, footer, language and currency switchers and every nav link.

## Assumptions

- **Stub auth is a cookie holding a role**, gated by `ENABLE_STUB_AUTH=true` (in `.env.example` and the
  CI browser-test job only), like the gallery. It must never be enabled on a deployed environment. F-03
  replaces it with real sessions; the guards (`requirePortalSession`) stay.
- **One role, one portal** (PRD section 2). A role seeing only part of a portal (interpreter in the
  coordinator portal, finance in admin) needs the permission matrix from F-04, so every role sees its
  portal's whole menu for now.
- **Case 360 is `ops/cases/[id]`**; the other PRD screens are flat pages.
- **"Menus" in the website header are links** to index pages. Mega-menus listing treatments and
  hospitals need CMS content.
- **The public site's WhatsApp number comes from an environment variable** and the button is hidden
  without it, rather than shipping a fake number.
- **The portal is never indexed** (`robots.txt` disallows all, `noindex`).
- Search in the top bar is UI only.

## Review

An independent reviewer read the whole diff (it did not run the apps). It found no high-severity
problem in the stub auth, and a number of medium and low ones. Fixed:

- **Flag-off path now tested.** `session.spec.ts` mocks cookies and the router and proves that without
  `ENABLE_STUB_AUTH` a valid `super_admin` cookie is ignored, sessions cannot be created and every portal
  redirects to the login page; with the flag on, roles map to portals and wrong-portal users are sent home.
  Also checked by hand against a production build without the flag: no app shell in the response for a
  forged cookie, and the login page says sign-in is not available.
- **A forgotten `NEXT_PUBLIC_SITE_URL` no longer lets crawlers in.** `robots.txt` disallows everything
  until the site is given its real address; an invalid value fails the build with a clear message.
- **Canonical URL, `x-default`, per-page Open Graph** (title, description, url) and `en_US`/`ar_AE`
  locales on the website.
- **Breadcrumb landmark** has its own name ("Breadcrumb"), no longer a second "Main navigation"
  (axe `landmark-unique` is now part of the tests).
- **Mobile panels close on any link**, the logo and the call to action included (they stayed open
  before); tests for both the website and the portal.
- **Blocked browser storage**: the collapsed-sidebar choice now really works in memory (the earlier
  comment was wrong and its test asserted nothing).
- Accessibility scans now cover all five portal homes, the collapsed sidebar, the open user and
  notification menus and the phone menu, in both languages.
- `aria-expanded` no longer duplicates the changing label; the collapsed-sidebar tooltip opens on the
  correct side in Arabic; one page-level heading on the bilingual 404 and error pages; the quote
  placeholder no longer links to itself; the gallery's demo link keeps its identity; dummy WhatsApp number
  in `apps/web/.env.example`; stale comments and two unused message keys removed.

**Not changed, on purpose**

- Every user's browser receives all portals' menu text (about 80 KB of catalogue, no data exposure:
  authorisation is on the server). Scoping the client messages per portal is a size optimisation for later.
- `error.tsx` and `global-error.tsx` are not exercised by a test (nothing throws yet); they are
  type-checked and reviewed only. The loading skeletons are likewise not asserted.
- The collapsed sidebar can flash expanded for a moment on load (the preference is read after hydration).
- The language switch drops the query string and hash; it matters once lists have filters.
- The stub cookie is `secure` when `NODE_ENV=production`, so the stub login only works over HTTPS or on
  localhost in a production build. Nothing in code stops the flag being set on a deployed environment;
  that is by convention (documented), until F-03 removes the stub.
- `global-error.tsx` and the website's standalone 404 import the whole catalogue through `loadMessages`.
