# S-05 — Design system (packages/ui)

## Goal

A design system in `packages/ui`: brand tokens (light theme, dark-ready), the full component list
from the task, all RTL-safe and keyboard accessible, and a `/ui-gallery` page in `apps/portal`
showing every component in English and Arabic, correct at 360 px and desktop widths.

## What was added

- **Tokens** (`packages/ui/src/theme.css`): semantic CSS variables (background, foreground, card,
  popover, primary, secondary, muted, accent, destructive, success, warning, info, border, input,
  ring, radius), a brand scale, light values and a complete `.dark` set. Fonts self-hosted through
  Fontsource: Inter (Latin) and Noto Sans Arabic.
- **Components** (`packages/ui/src/components`, 40 files): Button, Input, Textarea, Label, Select,
  Combobox, DatePicker, PhoneInput, CurrencyInput, Checkbox, Radio, Switch, Badge, StatusBadge, Card,
  Tabs, Dialog, Sheet, Drawer, Toast, Tooltip, DropdownMenu, Popover, Avatar, Skeleton, EmptyState,
  ErrorState, PageHeader, Breadcrumbs, ConfirmDialog, DataTable, FormField and nine ready-made
  `Form*` fields, FileUploader, StageTracker, Timeline, ChatPanel, StatCard, KanbanBoard, UiProvider.
- **Helpers** (`src/lib`): `cn`, money parsing/formatting in minor units, CSV export with
  spreadsheet-injection protection, upload restriction checks, kanban move logic.
- **`packages/contracts`**: the 12 case stages, 3 exit stages and 17 status values (PRD section 3) as
  constants, because StatusBadge and StageTracker need them. F-10 adds the state machine on top.
- **Gallery** (`apps/portal/app/[locale]/ui-gallery`): 33 sections, a language switcher, a mock S3
  multipart endpoint (`apps/portal/app/api/ui-gallery/s3`) so the uploader runs for real. Off in
  production unless `ENABLE_UI_GALLERY=true`.
- **Messages**: `gallery.*` and `stages.*` in `packages/i18n` (en and ar), `REVIEW.md` for the
  machine-drafted Arabic.
- **Tooling**: shared `react` ESLint preset with the hooks rules, jsdom test setup, a `gallery`
  Playwright project, `@axe-core/playwright`, the portal started with the flag in CI.

## Assumptions

- **Brand tokens were placeholders** (`<colour>`, `<font>`). Chose clinical blue (primary,
  continuing S-01), warm amber (secondary), Inter + Noto Sans Arabic. Colours are CSS variables, so
  changing them is one file.
- **shadcn/ui was set up by convention, not by its CLI** (needs a registry download, and a CLI-generated
  `components.json` adds nothing here). Components are Radix + `cva` + `cn`, in place.
- **TanStack Table 8.x and react-day-picker 9.x**, although 9.x and 10.x are the registry latest. Those
  majors have different APIs; the lines used are the ones this code was written against.
- **Latin digits in Arabic** for dates, money and phone numbers. These are checked against invoices and
  passports that use Latin digits, and mixed digit systems cause misreadings.
- **No built-in text.** Components take translated strings from the app, so the library holds no language.
- **Dark mode is defined and verified but not switchable** in the apps (no toggle yet).
- **Uppy 6's S3 plugin** signs each request through a `signRequest` callback; the API's file service
  (F-06) will implement it. Resume across page reloads is not included (it needs Uppy's Golden
  Retriever); retry within a session is.

## Defects found by looking and by running (not by `pnpm check`)

1. The S-01 layouts hard-coded `bg-white text-slate-900` on `<body>`, so dark mode left the page
   white. Fixed, and a test now forbids hard-coded neutral colours.
2. Chat meta line and attachment sizes reordered in Arabic ("(KB 240)", date before author). Fixed with
   `<bdi>` / `dir="ltr"` isolation.
3. Names with `dir="auto"` snapped to the wrong edge in right-to-left cards. Fixed with `<bdi>`.
4. `ConfirmDialog` let a failing `onConfirm` escape as an unhandled rejection and showed nothing.
   It now stays open, shows an error and reports it.
5. Badge text on tinted backgrounds failed WCAG AA contrast (axe). Added darker text tokens.
6. The sideways-scrolling stage tracker was not keyboard-reachable (axe). Made focusable.
7. Kanban screen-reader announcements: "picked up" was immediately overwritten and positions were off by
   one. Fixed.
8. A form field whose row-mate had a hint sat lower than it (grid stretch). Fixed with `content-start`.
9. `packages/ui` did not declare `tailwindcss` (found in S-04); S-05 uses it from the start.

## Tests

- **Unit** (jsdom, 98 tests in `packages/ui`, plus `contracts` and `i18n`): money parsing and formatting
  (including float traps and Arabic digits), CSV export and formula neutralising, upload restrictions,
  kanban moves, DataTable (sort, page, select, hide column, export, states), forms (label/hint/error
  wiring, server errors, currency, phone, combobox), dialogs, chat, uploader rejections, the stage and
  status components, message-catalogue parity, **no physical left/right classes**, **no hard-coded colours**.
- **Browser** (Playwright, `gallery` project, 34 tests): every section present in en and ar at 360 px and
  1280 px; correct `lang`/`dir`; no sideways overflow; axe WCAG 2 A/AA with no violations; tracker vertical
  on phones and horizontal on desktop; data table end to end including a real CSV download and a
  5,000-row virtualised table; currency and phone; combobox and date picker by keyboard; dialog focus
  trap and return; sheet, drawer, tooltip (including Tab-to-open), menu, toast; confirm dialog; the whole
  form including a server error; chat; kanban by keyboard (with announcements) and by mouse; **real S3
  multipart upload and a retry that re-sends only the failed part**; Arabic digits and mirrored layout.
- Plus the existing website smoke tests: 38 browser tests in total.

## Verification

`pnpm check` (42 tasks), `pnpm build` (11 workspaces), `actionlint`, and the full Playwright run (38 tests)
against production builds with the web and portal apps started the way CI starts them. The gallery was
also **looked at**: screenshots in English and Arabic at 360 px and desktop, and in dark mode. With the
flag unset, `/en/ui-gallery`, `/ar/ui-gallery` and the mock S3 endpoint all return 404.

**Not verified:** the new CI steps have not run on GitHub yet (they run when this is pushed to `develop`).
Dark mode and the Arabic copy have not been reviewed by a person. Screen-reader behaviour was checked
through automated accessibility rules and ARIA attributes, not with a real screen reader.
