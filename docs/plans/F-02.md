# F-02 — Master data module (the reference pattern)

## Goal

Admin CRUD for the eight master tables (countries, languages, currencies, specialities, treatments, cities,
document types, lost reasons): API, `/admin/masters` screens, audit events, seed. Every later module copies this
one, so it follows `CLAUDE.md` to the letter: thin controller, service, Zod contracts, cursor pagination, server
filters and sorting, soft delete, permissions, audit in the same transaction, API e2e tests with a forbidden role.

Acceptance: an admin adds a treatment in English and Arabic and it appears in the list at once.

## Design

- **One resource-driven module** (`apps/api/src/modules/masters`, the path the `scaffold-module` skill names; ADR 003).
  `MastersController` serves `/masters/:resource` for all eight tables; each table is an _adapter_: key kind (code or uuid), searchable and sortable
  fields, filters, translated fields, Zod create/update schemas (from `packages/contracts`). The service holds the
  logic once. A new master table is one definition, not another controller.
- **Contracts** (`packages/contracts/src/masters.ts`): resource names, create and update schemas, list query, the
  row shape, the field metadata the admin screens use to draw their forms. Cursor pagination primitives
  (`cursorQuerySchema`, `cursorPageSchema`) go in `primitives.ts` for every later list.
- **Cursor pagination** uses Prisma's native cursor on a stable `(sort field, key)` order; the cursor is opaque
  (base64 of the key). `total` is returned so the table can say "86 results". The admin DataTable keeps a stack of
  cursors, so previous/next work without offsets.
- **Soft delete.** Tables with `deletedAt` (specialities, treatments, cities, document types, lost reasons):
  `DELETE` sets `deletedAt` and `active=false`; `POST .../restore` brings it back. Country, language and currency
  have no `deletedAt` (reference tables keyed by ISO code): `DELETE` answers 409 and the screen offers "deactivate".
- **Translations.** English lives on the row, other languages in `<Entity>Translation` rows. The write body carries
  `translations: { ar: { name } }` (treatments also `summary`); an update that includes `translations` replaces them.
- **Permissions.** `@Can(action, subject)` plus `PermissionsGuard` exist from this task with the subject
  `MasterData`: any signed-in user may read, only `super_admin` may create, update, delete or restore. F-04 replaces
  the interim matrix with the full CASL one behind the same decorator.
- **Authentication is a stub until F-03.** `StubAuthGuard` reads the role from `x-stub-role` or the portal's
  `mt_stub_session` cookie, only when `ENABLE_STUB_AUTH=true`; the API refuses to boot with it enabled in production.
  The actor has a role but no user id, so audit rows carry `actorRole` only.
- **Audit and outbox.** Every create, update, delete and restore writes an `AuditEvent` (before/after) and an
  `OutboxEvent` (`master.created|updated|deleted|restored`) in the same transaction as the change.
- **Admin screens** (`apps/portal`, route `/admin/masters` and `/admin/masters/[resource]`): a resource switcher,
  the shared `DataTable` (server search, sort, active filter, cursor paging, CSV), an edit `Sheet`, a create
  `Dialog`, a `ConfirmDialog` for delete; forms are React Hook Form + `zodResolver` with the contract schema, and
  server errors land on the field. Loading skeleton, error and empty states come from `DataTable`.
  Data goes through the generated hooks (`pnpm api:generate`).
- **Seed** grows to the task's list: all countries with ISO codes and dialling codes, 10 languages, 11 currencies,
  25 specialities, 60 treatments, 15 Indian cities, document types and the PRD lost reasons, with Arabic names.

## API

| Method and path                       | Permission        | Notes                                                                                      |
| ------------------------------------- | ----------------- | ------------------------------------------------------------------------------------------ |
| `GET /masters/:resource`              | read MasterData   | `q`, `active`, `deleted`, `sort`, `cursor`, `limit`, `specialityId`, `countryCode`, `kind` |
| `GET /masters/:resource/:id`          | read MasterData   |                                                                                            |
| `POST /masters/:resource`             | create MasterData | 201; 409 on a duplicate key or slug                                                        |
| `PATCH /masters/:resource/:id`        | update MasterData |                                                                                            |
| `DELETE /masters/:resource/:id`       | delete MasterData | soft delete; 409 where the table has no `deletedAt`                                        |
| `POST /masters/:resource/:id/restore` | update MasterData |                                                                                            |

## Tests

- Unit (Vitest): cursor encoding, sort parsing, the interim permission check, definitions cover every resource and
  match the Prisma models, stub-auth parsing.
- API e2e (real PostgreSQL, throwaway database): every endpoint for every role class (admin, case manager, no
  sign-in), validation errors, duplicates, pagination across pages, search, filters, soft delete and restore,
  translations replace, audit and outbox rows, `deleted` filter.
- Playwright: admin signs in (stub), adds a treatment in English and Arabic, sees it in the list; a case manager
  cannot reach the buttons; Arabic layout; axe on the list.

## What was added

- **`packages/contracts`**: `masters.ts` (resources, create and update schemas, list query, row, `MASTER_DEFINITIONS`),
  `permissions.ts` (interim `can`), cursor pagination in `primitives.ts`.
- **`apps/api`**: `database` (Prisma client provider), `auth` (`@Can`, `@Public`, `StubAuthGuard`, `PermissionsGuard`),
  `audit` and `outbox` services, `common` (cursor, request context), `modules/masters`. `ENABLE_STUB_AUTH` in the env
  schema (refused in production) and in `.env.example`. Dependency: `fastify` (types for the request, same version
  Nest already installs).
- **`packages/db`**: seed grown to the task's list (`prisma/seed-data/*`): 245 countries from libphonenumber's metadata
  with CLDR English and Arabic names (dev dependency `libphonenumber-js`, already in the workspace through
  `packages/ui`), 10 languages, 11 currencies, 25 specialities, 60 treatments, 15 cities, 12 document types and
  8 lost reasons. The seed never overwrites an existing row.
- **`packages/api-client`**: orval config fixed so POST/PATCH/DELETE become mutations (S-01 forced `useQuery` for
  every operation); fetcher rewritten to orval 8's call shape; the package now builds the generated client
  (`generated/` is compiled into `dist`).
- **`packages/ui`**: `FormInput` and `FormTextarea` accept `dir`, for the Arabic fields.
- **`apps/portal`**: `/admin/masters` (index) and `/admin/masters/[resource]` (list, add dialog, edit sheet, row
  menu, delete confirmation), `components/masters/*`, `ApiQueryProvider` in the portal layout, `@tanstack/react-query`
  dependency. The nav key `master-data` became `masters` so the URL matches the task.
- **i18n**: `masters.*` in English and Arabic (machine-drafted Arabic is listed in `packages/i18n/REVIEW.md`).
- **CI**: the browser job now has a Postgres service, migrates and seeds, and starts the API with the stub sign-in
  (`NODE_ENV=test`, because production refuses it) and the portal as an allowed origin.

## Changes to earlier code

- `apps/api`: `openapi:export` runs the compiled build (tsx/esbuild does not emit the decorator metadata Nest needs
  for DTOs and injection). `eslint.config.mjs` tells the parser about decorator metadata so
  `consistent-type-imports` leaves injected classes alone.
- `packages/api-client`: see above; `turbo.json` makes its lint, typecheck and test wait for its build.
- Contracts and db spec lists of non-database schemas grew (`masterResource`, `translationLocale`,
  `permissionAction`, `permissionSubject`).
- The F-01 seed no longer overwrites currencies and languages, and its currency list is the task's.

## Verified

`pnpm check` is green. The API was built and started as in production (`node dist/main.js`) and the portal was
built and started with `next start`; Playwright drives the admin screens against them (see `e2e/tests/portal-masters.spec.ts`).
