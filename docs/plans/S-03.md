# S-03 — Claude Code configuration and progress tracker

## Goal

Create the Claude Code configuration written in `docs/BUILD_PLAN.md` section 5, the progress
tracker, a first architecture decision record and a dev-users placeholder.

## What was added

- `CLAUDE.md` — the rules from section 5.1.
- `.claude/skills/` — `task`, `review-task`, `security-check`, `scaffold-module` (section 5.2).
- `.claude/agents/` — `code-reviewer`, `security-reviewer` (section 5.3).
- `.claude/settings.json` and `.claude/hooks/protect-files.sh` (executable) (section 5.4).
- `docs/progress.md` — a checklist of all 116 tasks in the plan, grouped by phase, with S-01 to
  S-03 ticked. The deferred-work notes from earlier tasks are kept under "Notes and deferred work".
- `docs/decisions/001-architecture.md` — the section 3 stack choices, plus the versions actually
  installed.
- `docs/dev-users.md` — placeholder; the seed users arrive with F-11.

The skill, agent and settings files were extracted from the plan's fenced blocks by script, not
retyped, so they match the plan exactly except for the deviations below.

No API endpoints, data model, permissions, UI or i18n keys change.

## Deviations from the plan text

1. **`CLAUDE.md` commands line.** The plan says `pnpm check` includes API e2e. It does not
   (API e2e needs Testcontainers, which arrive with the first endpoints), so the line now says
   what `pnpm check` runs and names the separate API e2e command.
2. **`CLAUDE.md` logger path.** `apps/api/src/logger.ts` does not exist; the redact list lives in
   `apps/api/src/logging/logger.options.ts`.
3. **`CLAUDE.md` "Stack notes" section (new).** Eight lines recording what S-01 and S-02 learned:
   current major versions, `.js` import specifiers in Nest versus none in Next, how Next inlines
   `NEXT_PUBLIC_*`, shared packages needing a rebuild, and to boot the app rather than trust
   `pnpm check`. Future sessions read this file first, so these are the mistakes most worth preventing.
4. **`settings.json` keeps `"effortLevel": "high"`.** Required by `loop/CLOUD.md` for any
   `.claude/settings.json`.
5. **Formatting hook hardened.** `jq -r '.tool_input.file_path // empty'` and `xargs -r`, so a tool
   call with no file path does not run Prettier on the literal string `null`.
6. **`protect-files.sh` allows `.env.example`.** The plan says to block `.env`, but `CLAUDE.md`
   tells sessions to add new variables to `.env.example`; matching it would make that
   impossible. It blocks `.env` and `.env.*` except `.env.example`.
7. **`CLAUDE.md` "Plan first, wait for approval"** is copied as written. In unattended runs
   `loop/prompts/autonomous-rules.md` rule 1 overrides it, which that file states.

## Tests

No application code changed. Verified by running (below).

## Assumptions

- The `/task` skill appears in the slash menu from the folder name and the `name:` field in its
  frontmatter; both match for all four skills and both agents (checked by script).
- `docs/progress.md` ticks S-03 as part of this task, as the task text says.

## Verification

- The hook script, fed the JSON Claude Code sends: blocks `.env`, `.env.local`, `.git/config` and
  `pnpm-lock.yaml` (exit 2 with a message); allows `.env.example`, ordinary source files,
  `docs/environment.md` and a call with no file path (exit 0).
- The formatting hook command from `settings.json`, run on a deliberately unformatted
  TypeScript file, reformatted it; it also exits 0 when there is no file path.
- Frontmatter of every skill and agent parses and the names match their directories.
- `docs/progress.md` contains exactly the 116 task IDs in the plan.

**Not verified here:** that `/task` actually shows in a Claude Code slash menu, and that the hooks
fire from a live session. Skills and settings are loaded when a session starts, and this
session started before they existed. Start a new Claude Code session in the repo and type `/` to
confirm.
