# F-01 — Database schema

## Goal

The full Prisma schema for every entity in PRD section 11 and the screens of sections 5 to 9, one
migration that applies cleanly on an empty database, full-text search on hospitals, doctors, treatments
and patients, and `docs/data-model.md` listing the entities and their relations.

## What was added

- **`packages/db/prisma/schema.prisma`**: 71 models and 47 enums.
  - All entities named in the task, plus the ones the PRD implies and the later tasks will need:
    `StaffProfile`, `HospitalStaff`, `Accreditation`, `CaseAttendant`, `CaseStageHistory`, `DocumentShare`
    (a hospital sees a document only through a live, patient-consented share), `CommissionRule`,
    `MessageAttachment`, `StayHospitalDistance`, `NumberSequence` (the counters behind `CASE-YYYY-NNNNNN`,
    `INV/YY-YY/NNNNN`, `Q-NNNNNN`), and translation tables for Country, Speciality, Treatment, City,
    DocumentType, LostReason, Hospital, Doctor and Package.
  - Conventions in the header of the file and in `docs/decisions/002-database-conventions.md`.
- **`packages/contracts/src/enums.ts`**: the 44 database enums that were not already there (user status,
  urgency, document kind, payment status, ...), as constants and Zod schemas. Roles and case stages stay in
  `roles.ts` and `case-stages.ts`.
- **One migration**, `prisma/migrations/*_f_01_schema`: tables, enums, indexes and foreign keys from Prisma,
  plus hand-written SQL for the extensions (`pg_trgm`, `unaccent`), `f_unaccent()`, the search triggers, 32 `CHECK`
  constraints, one partial unique index and the append-only audit trigger.
- **Search**: `searchVector tsvector` on Hospital, Doctor, Treatment and Patient (patient: name, phone as typed
  and digits only, passport number, email), kept current by triggers, with GIN indexes.
- **`docs/data-model.md`**: generated from the schema by `pnpm --filter @medtravel/db docs:model`; a test fails
  when it is stale.
- **Seed** (`pnpm db:seed`, idempotent): currencies (including a 0- and a 3-decimal one), languages, 21 source
  countries, 6 cities, 6 specialities, 10 treatments, 9 document types and 8 lost reasons, with Arabic names.
- **Tests**: 11 static tests (`pnpm check`: enum parity with the contracts, conventions such as UUID keys, no
  floats, an index on every foreign key, soft-delete columns, the docs being current) and 20 database tests
  (`pnpm --filter @medtravel/db test:e2e`, run in CI against the Postgres service: migrations on an empty database,
  every check constraint, uniqueness, the audit trigger, accent-insensitive search in English and Arabic, the GIN
  index being used).
- **CI**: the API e2e job also runs the database tests.

## API, UI, events

None. No endpoints, screens or events; this task is the foundation F-02 onward build on.

## Assumptions

- **Money columns are 32-bit `Int`** as the task says; see ADR 002 for the ceiling and the escape hatch.
- **Trigger-filled search columns**, not generated ones (Prisma would fight a generated column forever).
- **Entities beyond the list** (above) were added because the PRD's own features need them; none is speculative.
- **Document sharing is a join table** (`DocumentShare`), not a flag on `Document`, so a hospital's access
  is per document, per hospital, revocable and tied to a `Consent`.
- **Agent referral links** are `Agent.referralCode`; the `Case.agentId` is set when a case arrives through one.
- **Bank and payout details** are `Json` columns that the application encrypts; the schema does not.
- **`Patient.passportNumber` is stored as text** (the application may encrypt it). It is searchable, which an
  encrypted value would not be; if encryption at rest is required, search by passport moves to a blind index.
- **Enum values for the statuses not in the PRD** (payment, quote, booking, task, incident, ...) were chosen from
  the flows in sections 5 to 9; later tasks can add values with a migration.
- **Table names are Prisma's defaults** (PascalCase, quoted in SQL), not snake_case.

## Changes to earlier code

- **`packages/db/turbo.json`** makes the package's `lint`, `typecheck` and `test` wait for its own `build`. All of
  them ran `prisma generate` at the same time, which was harmless while the schema was empty and now collided
  ("generated/prisma exists and is not empty but doesn't look like a generated Prisma Client").
- **`.prettierignore`** lists `docs/data-model.md`, which is generated and compared byte for byte by a test.
- **`pnpm-lock.yaml`** gains `@medtravel/contracts` as a dev dependency of `packages/db` (workspace link, for the enum parity test).
