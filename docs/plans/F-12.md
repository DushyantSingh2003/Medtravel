# F-12 — Observability

## Goal

When something breaks we can find it: every request has an ID that appears in the logs, the audit rows, the response, the jobs it
queued and the error report, and no report carries personal data.

## Design

- **`@medtravel/observability`**: `scrub` (browser-safe: removes cookies, headers, request bodies, query strings, emails, tokens, long
  numbers, locals from stack frames; reduces the user to an id), request-ID helpers (accept a well-formed incoming `X-Request-Id`,
  else generate; `AsyncLocalStorage` so code that never sees the request can read it), `initSentry` / `captureError`, and
  `nextSentryOptions` for the two Next apps.
- **API**: Fastify generates the ID (`createFastifyAdapter`), an `onRequest` hook sets the response header and the async context, the
  pino logger adds `requestId` to every line, `OutboxService.publish` records the ID in the event payload, and
  `SentryExceptionFilter` reports unexpected errors (not 4xx) with the ID, route pattern and user id, and logs them scrubbed.
  `GET /metrics` (Prometheus text; request latency histogram by route pattern, queue sizes per state, outbox backlog, slow-query
  count, process metrics) needs `METRICS_TOKEN` (required in production). `GET /health/ready` checks database, Redis and the bucket
  with a 2 s timeout each and answers 503 without detail; `GET /health` stays a plain liveness probe. Queries over `SLOW_QUERY_MS`
  (200) are logged as warnings with the SQL text only. `/admin/queues` is Bull Board, read-only, super admin with a finished second
  factor only (checked before the board is reached).
- **Worker**: Sentry, slow-query logging, and each outbox handler runs under the request ID recorded in its event (falling back to the
  event id); failures are reported with the job type and rethrown so the outbox retries; error messages in logs are scrubbed.
- **Website and portal**: `@sentry/nextjs` with the shared options (`instrumentation.ts`, `instrumentation-client.ts`, server and edge
  configs); when `SENTRY_AUTH_TOKEN` is set, `withSentryConfig` uploads source maps, tags the release (`SENTRY_RELEASE`) and deletes
  the maps from the build.
- The API client sends a fresh `X-Request-Id` with each call and puts the one the API answered with on `ApiError.requestId`.

## Assumptions

Traces are off (`tracesSampleRate: 0`) until we know the volume. Prometheus scrapes the API only; the worker's health is its queue
and outbox numbers as seen from the API. The queue names are in `@medtravel/contracts` and a worker test keeps them in step.
